FreshBite — Online Food Ordering Website

Project report — front-end prototype demonstrating restaurant browsing, cart management, and checkout flows.

Objective

Build a responsive, user-friendly front-end prototype that demonstrates the end-to-end ordering experience: browse restaurants and menus, view products, add items to a cart, and complete a checkout flow. The site is intended as a working demo and a foundation for future backend integration.

Technologies

  • HTML5 & CSS3 (modular styles: `style.css`, `components.css`, `responsive.css`, `animations.css`)
  • Vanilla JavaScript for client logic (files such as `app.js`, `auth.js`, `products.js`, `restaurant.js`, `cart.js`, `checkout.js`, `storage.js`, `ui.js`, `utils.js`)
  • Static assets organized under `assets/` (images, icons)
  • Static hosting friendly — ready for a CDN or simple web server

Key Features

  • Restaurant & Menu Listings: Browse restaurants and navigate to menu items with images and short descriptions.
  • Product Detail Pages: Item details, quantity selection, and add-to-cart actions.
  • Persistent Cart: Add/remove/update items with persistence via `localStorage`.
  • Checkout Flow: Order summary and confirmation mock-up to illustrate the purchasing sequence.
  • Demo Authentication: Login and registration UI to simulate user sessions (client-side only).
  • Responsive Design: Mobile-first layout and component breakpoints for multiple viewports.

System Design & Organization

The codebase follows single-responsibility practices: each JavaScript module manages a focused domain (cart, auth, products). `data.js` contains demo data while `storage.js` abstracts `localStorage` operations to simplify future backend replacement. CSS is layered for components, utilities, and responsive rules.

Learning Outcomes

  • Modular front-end architecture and disciplined file organization.
  • Client-side state management and persistence techniques.
  • Improved responsive UI skills and practical DOM/event handling.
  • Experience prototyping UX flows without a backend while keeping code ready for integration.

Challenges & Solutions

Cart synchronization: Kept consistent across pages by hydrating state on page load and centralizing reads/writes in `storage.js`.

Responsive edge cases: Addressed via component decomposition, targeted breakpoints, and image handling rules.

Auth without a server: Implemented client-side stubs and documented the demo-only nature to avoid security confusion.

Future Improvements

  • Backend API for secure auth, order persistence, and inventory.
  • Payment gateway integration with server-side validation.
  • Search, filters, ratings, and improved discoverability.
  • Accessibility enhancements (ARIA, keyboard navigation) and automated tests with CI.

Prepared for demonstration and submission.
